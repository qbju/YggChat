# YggChat

NAT越え不要のP2Pチャット（Yggdrasil内蔵）。現在のバージョン: **v0.19.0**

> **ベータ版です。** 更新が多く、互換性のない変更（古い版どうしだと一部の機能が通じない、保存形式や通信形式が変わる等）もしばらくは頻繁に入ります。できるだけ最新版を使い、相手にも更新してもらってください。

[![build](https://github.com/qbju/YggChat/actions/workflows/build.yml/badge.svg)](https://github.com/qbju/YggChat/actions/workflows/build.yml)

## 使い方

| 環境 | 使い方 |
| --- | --- |
| PWA（インストール不要） | <https://yggchat.surge.sh/> |
| Windows | `yggchat-windows-amd64.exe` をダブルクリック → アプリのウィンドウ（WebView2）が開きます。WebView2ランタイムがない環境では既定のブラウザで鍵付きの `http://127.0.0.1:7780/?k=…` を開きます |
| Android | APK版推奨。Termuxなら `yggchat-android-arm64` |
| Linux | `./yggchat-linux-amd64` |

- データ: `~/.yggchat/`（`node.json` = 秘密鍵、`chat.json` = 履歴、どちらも `0600`）
- オプション: `-peers` `-listen` `-ui` `-data` `-cli` `-nowindow` `-licenses`
- Windows版はウィンドウを閉じると終了します。`-nowindow` を付けると従来どおりウィンドウを出さずにブラウザから使えます。2回起動した場合は動いているノードのウィンドウを開くだけです。
- ビルド済みファイルは [Releases](https://github.com/qbju/YggChat/releases) / [Actions](https://github.com/qbju/YggChat/actions) と、アプリの設定→ダウンロードから入手できます。

## リンクとURLスキーム（v0.17.0〜）

| リンク | 意味 |
| --- | --- |
| `https://yggchat.surge.sh/#add=<アドレス>&n=<名前>` / `yggchat://add/<アドレス>?n=<名前>` | 相手を追加 |
| `https://yggchat.surge.sh/#j=<コード>` / `yggchat://join/<コード>` | グループに参加（コードは43文字） |

- Android版は `yggchat://` と `web+yggchat://` を開けます。`https://yggchat.surge.sh/` のリンクも開けますが、Androidの「対応リンクを開く」をアプリ設定でオンにする必要がある場合があります（自動確認はしていません）。
- PWAはインストールしたChrome系ブラウザ（主にパソコン）で `web+yggchat://` を受け取れます。ブラウザは `yggchat://` のような独自スキームをWebアプリに渡せないためです。
- Windows / Linux版のスキーム登録はまだです。https のリンクを使ってください。
- 新しいチャットのアドレス欄に貼り付けたり、QRで読んだりしても使えます。

## 端末のYggdrasilを使う（VPN型アプリと併用）

Yggdrasil公式Androidアプリや、PCで常駐しているyggdrasilサービス（TUN）があれば、**設定→ピア→「端末のYggdrasilを使う」** でそちら経由に切り替えられます（またはデータフォルダに `system-ygg` ファイル、環境変数 `YGGCHAT_SYSTEM=1`）。

- アドレスは端末側Yggdrasilのものになり、ピア設定もそちらで行います。
- 内蔵ノードの鍵は残るので、オフにすれば元のアドレスに戻ります。
- このモードではNostr置き配は使えません。
- 受信はUDP 7777番をOS上で待ち受け、送信元が `200::/7` のものだけを受け付けます。

## YggChatを端末のYggdrasilにする（Android VPNモード）

**設定→ピア→「YggChatを端末のYggdrasilにする（VPN）」** をオンにすると、公式アプリの代わりになります。

- `200::/7` 宛てだけをVPN（TUN）で受け持ち、ブラウザやSSHなど他のアプリもYggdrasilに接続できます。
- アドレス・鍵はYggChatのまま。通常のネット通信はVPNを通りません（allowBypass / IPv4は素通し）。
- TUNのfdは同じアプリ（同じUID）からだけ受け取ります。公式アプリのVPNとは同時に使えません。
- **「外からの接続」** で、Yggdrasil上の他人からこの端末への接続を選べます: すべて閉じる（既定）／指定ポートだけ開ける／すべて開ける。
  閉じている間も、自分から開いた接続の返事・YggChatのチャット（UDP 7777）・オン時のfingerは通り、それ以外は黙って捨てる（pingにも答えない）ので、外からは空のホストに見えます。

## LANチャット（アプリ版のみ・既定オフ）

**設定→LANチャット** をオンにすると、Yggdrasilのマルチキャスト探索で同じWi-Fi・有線LAN・テザリング上のノードを見つけ、リンクローカルで直接ピアになります。インターネットや公開ピアがなくても同じLAN内で会話できます。

- 「近くのノード」に表示名（互いにLANで直接つながっている相手とだけ交換）とアドレスが出て、「話す」で開けます。
- LANパスワードを設定すると、同じパスワードのノードとだけピアになります（Yggdrasil公式のmulticast Password）。
- オンの間、同じLANの人にはあなたのアドレスと表示名が見えます。Androidでは有効中だけMulticastLockを取ります。
- システムYggdrasilモードでは端末側Yggdrasilの設定に従います。PWAはLANを使えません。

## finger（.plan公開・既定オフ）

**設定→finger** をオンにすると、Yggdrasil上の誰でも `finger @[あなたのアドレス]`（TCP 79番, RFC 1288）で表示名と `.plan` を見られます。

- オンライン状態・連絡先・鍵などは返しません。転送（`user@host@host`）は拒否します。
- オフの間はTCP 79番の待ち受け自体を閉じ、UDPの問い合わせにも無言なので、外からYggChatだと見分けられません。
- 他人をfingerすると、問い合わせ先にはあなたのアドレスが見えます。
- アプリ内の「fingerで調べる」や連絡先の「finger」ボタンで、他のYggChat（UDPの `{t:"fq"}`）や一般のfingerサーバー（TCP 79）を問い合わせられます。
- AndroidのVPNモードではOSが79番を開けないため、TUNの中継で79番⇔7979番を付け替えます。
- PWAはTCPを使えないので、YggChat同士の問い合わせだけ対応です。

## メッセージの編集・削除

吹き出しを長押し（PCは右クリック）→ コピー／編集／自分の画面から削除／相手の画面からも削除。

- 編集と送信取り消しは自分のメッセージだけで、相手は元の送信者のアドレスからの指示しか受け付けません。
- 相手がオフラインなら、つながったときに反映されます。
- すでに読まれた内容やNostr置き配に預けた分は消せません。

## 端末移行（v0.15.0〜）
設定 →「端末移行」。PWAとアプリの間でも移せます。
- **新しい端末**で「この端末で受け取る」→ 移行コード（ygm1:…）とQRが出ます。
- **古い端末**で「この端末から送る」→ カメラでそのQRを読む（カメラがなければコードを入力。履歴も移すか選べます）。鍵とデータはYggdrasil経由で直接届きます（LAN不要・別の回線同士でもOK・途中で切れても続きから再送）。
- 中身は新しい端末がその場で作った使い捨てのX25519鍵あてに暗号化（AES-256-GCM）されるので、コードを持つ端末以外は読めません。コードは自分の端末にだけ入れてください。
- 終わったら古い端末のIDは消してください（同じIDを2台で動かすと届かなくなります。完了時に案内が出ます）。
- 片方しか手元にない時は「バックアップを書き出す／読み込む」（パスフレーズで暗号化した .ygb ファイル）。Androidアプリ版はファイル保存に未対応なので直接転送を使ってください。

## 確認済みドメイン（v0.14.0〜）

設定のプロフィールにドメイン（例: `chat.example.com`）を入れると、プロフィールと一緒に相手へ届きます。受け取った側は、そのドメインのAAAAレコードを引き、送ってきた人のYggdrasilアドレスと一致したときだけ「✓ chat.example.com」と表示します。

- アドレス→ドメイン：プロフィールは本人の鍵から直接届くので、なりすましできません（逆引きDNSの代わり）。
- ドメイン→アドレス：AAAAレコードが一致することで、そのドメインの持ち主だと確かめます。
- 設定するときは、先にDNSでAAAAに自分のアドレスを登録してください（一致しないと保存できません）。確認は12時間ごとにやり直します。

## ドメイン名で追加（v0.13.8〜）

「新しいチャット」にドメイン名を入れると、そのドメインのAAAAレコードを引き、Yggdrasilアドレス（200::/7）が入っていればその相手と会話を始めます。自分のドメインに `chat.example.com AAAA 200:…` のように登録しておけば、アドレスの代わりにドメインを教えられます。

- 問い合わせはDNS-over-HTTPS（Cloudflare → Google）。SOCKS5オン時はプロキシ経由で、システムのDNSには落ちません（ネイティブ版はSOCKSオフでDoHが使えないときだけシステムのDNSを使います）。
- DNSはなりすましできるので、追加時に表示されるアドレスを確認してください。一度追加すれば、以降はアドレス（鍵）で通信します。

## プロフィールサイト（ベータ・アプリ版のみ・既定オフ）

設定の「プロフィールサイト」に書いたHTMLの1ページを、自分のYggdrasilアドレスの80番ポートで公開します（`http://[200:…]/`）。Yggdrasilにつながっている人なら、普通のブラウザでも見られます。

- オフの間は80番ポート自体を閉じます。公開中は、オンラインかどうかが外から分かります。
- 置けるのは1ページ（256KBまで）だけで、ほかのファイルやアプリの情報には一切アクセスできません。画像は `data:` URL で埋め込めます。
- 連絡先情報の「サイト」ボタンで、相手のページをアプリ内（自分のYggdrasilノード経由）で開けます。スクリプト・フォーム・外部の読み込みは無効にして表示します。
- AndroidのVPNモードでは8080番で待ち受けて80番に付け替えます。PWA（ブラウザ版）では公開も閲覧もできません。

## グループチャット（ベータ・v0.13.5〜）

「＋」→「グループを作る」で、連絡先（またはアドレス）からメンバーを選びます。人数の上限は最初24人で、ホストがグループ設定で24〜1024人から選べます（v0.19.0〜）。

- サーバーはありません。送ったメッセージはメンバー1人ずつに直接届け、オフラインの人にはつながったときに届けます（置き配オンなら、連絡先どうしのメンバーにはNostrにも預けます）。
- メンバー全員に、グループ名とメンバーのアドレスが共有されます。メンバーなら誰でも名前を変更できます。退出すると他のメンバーに通知されます。
- 作った人がホストです（v0.16.0〜）。メンバーの追加・削除はホストと副管理者だけができます。v0.16.0より前に作ったグループにはホストがいません（誰でも追加できる従来どおり）。
- 副管理者（v0.19.0〜、最大10人、ホストが任命）: 参加の承認、自分の招待リンクの発行、一般メンバーの追加・削除ができます。設定・パスワード・副管理者の任命はホストだけ。ホストがオフラインでも、副管理者がオンラインなら新しい人が入れます。ホストが退出すると、最初の副管理者がホストを引き継ぎます（副管理者がいないと、以後だれも追加・削除できません）。
- 25人以上のグループ（v0.19.0〜）: メンバー一覧が1パケットに収まらないので分割して送ります。メンバー全員がv0.19.0以上である必要があります。65人以上のグループでは、オフラインのメンバーへのNostr置き配はしません（リレーにメンバーの数だけ預けることになるため）。
- 連絡先でない人から招待されたグループは「招待」として表示され、参加するまで返信できません。
- 招待リンク（v0.17.0〜）: ホストと副管理者はグループ情報の「🔗 招待リンク」でリンクとQRを出せます。リンクは人ごとに別で、開いた人はリンクを出した人がオンラインのときに参加できます。「リセット」するとその人の前のリンクは使えなくなります（他の人のリンクはそのまま）。リンクにはホストのYggdrasilアドレス・グループID・合言葉（ランダム8バイト）が入っています。v0.17.0より前のホストのグループには使えません。
- グループ設定（v0.18.0〜、ホストだけが変更）: 写真を送れるか／参加に承認が必要か（ホストか副管理者が承認）／新しく入った人に過去のメッセージを見せるか／消えるメッセージ（5分〜4週間）／参加パスワード／人数の上限（v0.19.0〜）／投稿のPoW（v0.19.0〜、なし・3〜16ビット）。
  - 設定はメンバーの端末それぞれが守る仕組みです。v0.18.0より前の版のメンバーには効きません（写真を送れてしまう、消えない など）。改造したアプリも防げません。
  - 承認・パスワードは招待リンクから入る人に使います（ホスト・副管理者が直接追加する場合は不要）。パスワードはホストと副管理者の端末にだけハッシュ（PBKDF2-SHA256）で保存し、5回間違えると10分間受け付けません。
  - 過去のメッセージは、参加を受け付けた人（ホストか副管理者）の端末にある最新30件が新メンバーに届きます（写真は「📷」の文字だけ、長い文は省略）。中継した人を信頼する前提です。
- 写真も送れます（v0.16.0〜。v0.16.0より前の版のメンバーには、グループではなく1対1の写真として届きます）。編集・送信取り消しは1対1のみ。v0.13.5より前の版はグループのメッセージを受け取れません。

## 投稿のPoW（v0.19.0〜）

メッセージには、送る側の端末で少しだけ計算（プルーフ・オブ・ワーク）した値を付けます。大量のスパムを送るコストを上げるためで、ふつうに使う分には一瞬です。

- 1対1は3ビット、知らない人へのメッセージリクエストとグループへの参加は8ビット。グループの投稿はホストが「なし／3〜16ビット」から選べます（1投稿につき1回の計算で、メンバー全員分に使います）。
- 受け取る側が足りないと判断すると「何ビット必要か」を返し、送る側が自動で計算し直します。
- v0.18.0以前の版はPoWを付けません。互換のため、3ビット以下でよい場所ではPoWなしも受け取ります（v0.24まで）。設定の「リクエストと参加にPoWを必須にする」（既定オフ）をオンにすると、PoWなしのリクエストと参加を断ります。ホストがPoWを変えたグループでは、PoWなしの投稿は届きません。

## Tor / SOCKS5（ベータ・アプリ版のみ・既定オフ）

設定の「Tor / SOCKS5」をオンにすると、YggChatがインターネットにつなぐ通信（Yggdrasilのピア、Nostrリレー、公開ピア一覧の取得）をすべてSOCKS5プロキシ経由にします。Androidは[Orbot](https://orbot.app/)（127.0.0.1:9050）、PCはTor（9050）またはTor Browser（9150）を先に起動してください。

- 公開ピアやNostrリレーに、自分のIPアドレスが見えなくなります（Torの場合）。ホスト名はプロキシ側で解決します。
- プロキシが止まっていても直接はつながりません（接続中0になります）。tcp://・tls:// のピアだけ使い、quic://・ws:// のピアは使いません。
- 自分で設定した待ち受け（`-listen`）、LANチャット、端末のYggdrasil／VPNモードは対象外です。PWA（ブラウザ版）では使えません。
- Torを通しても、置き配の宛先タグの組み合わせや、Yggdrasil上の相手とのやりとりそのもの（相手のアドレス）は消えません。

## 端末チャット（CLI）

```sh
./yggchat-linux-amd64 -cli        # Termux: ./yggchat-android-arm64 -cli
```

同じ `-ui` でノードが動いていればそれにつながり、なければその場でノードを起動します（ノードのログは `データ/node.log` へ）。

`/help` でコマンド一覧。`/list`、`/open <番号|名前>`、`/add <アドレス> [名前]`。それ以外の入力は開いている相手に送信。受信はリアルタイムで表示されます。

## 暗号と通信の仕組み

- メッセージはYggdrasilのセッション暗号で端末間エンドツーエンドに暗号化されます。アドレスは公開鍵から導出されるため、QR／招待リンクでアドレスを確認すれば相手の鍵も確認できます。
- 受信メッセージの送信者は、Yggdrasilが暗号的に保証する送信元IPv6アドレスで判定しています（自己申告は使いません）。
- **ネイティブ版**: ノードは端末内で動作。UI/APIはループバック（`127.0.0.1`／`[::1]`／`localhost`）でしか待ち受けられず、接続元アドレス・Host／Origin／Content-Typeを検証します。さらにデータフォルダの `ui-key` に置いた鍵（Cookieまたは `X-YggChat-Key` ヘッダー）がないリクエストは拒否するので、同じ端末の他アプリ・他ユーザーからも操作できません（同じユーザー権限で動く悪意あるプログラムは鍵ファイルを読めるため防げません）。ブラウザで使う場合は起動時に表示される `http://127.0.0.1:7780/?k=…` を開いてください。
- **PWA版**: ノードはブラウザ内（WebAssembly）で動作し、秘密鍵と履歴はブラウザのIndexedDBにだけ保存されます。
  - ブラウザは生のTCP/UDPを開けないため、ブラウザのOriginを許可したYggdrasilピアにwssで直接つなぎます。
  - 既定は `ygg.being.pet`（2026-10-19時点で公開一覧から見つかった唯一のブラウザ可ピア）。
  - YggChat側の中継サーバーはありません。ピアが見るのは暗号化済みのYggdrasilリンク通信だけです（接続元IPと通信量・時刻は見えます）。
  - 自分でピアを立てる場合: Listen に `"ws://[::]:PORT?origin=https://yggchat.surge.sh"` を書き、TLS終端してwssで公開してください。
  - PWAはタブ／アプリを開いている間だけ動きます。
- パスコードを設定すると、端末内の履歴はAES-256-GCMで暗号化して保存されます（ネイティブ: scrypt、PWA: PBKDF2-SHA256 31万回）。ロック中は受信せず、相手側で保留されます。秘密鍵（`node.json`／PWAの鍵）は暗号化対象外です。
- オフラインの相手宛ては送信側の端末に「送信待ち」として残り、双方がオンラインになったときに自動で送ります。
  v0.13.6から、新しく始める人は「置き配（Nostr）」が最初からオンです（それ以前から使っている人の設定はそのまま。設定でいつでもオフにできます）。オンの間、届かなかった文章を相手の鍵で封をして公開Nostrリレーに最大7日預けます（相手もオンにしている必要あり）。
  リレーには中身・送信者・Yggdrasilアドレスは見えません。宛先タグは二人の鍵から作る値で、相手ごと・日ごとに変わり、連絡先同士でしか計算できません（知らない人はあなたの置き配を探したり大量に送ったりできない）。送信時刻は最大48時間ぼかし、長さは1KB/2KB/4KB…の段階にそろえます。それでもリレーには、預ける側と取りに来る側のIPアドレスと、1回の取得でどのタグをまとめて聞いたかは見えます（Torを通してもタグの組み合わせは見えます）。
- 知らない相手からはメッセージリクエストとして届き、承認するまでこちらの名前・自己紹介・アイコンは共有されません。

## ビルド

Go（`go.mod` のバージョン）が必要です。Twemojiの画像はリポジトリに含めていないので、最初に取得します。

```sh
./twemoji/fetch.sh                      # twemoji/svg.zip を作成
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w -checklinkname=0" .
GOOS=js GOARCH=wasm go build -trimpath -ldflags="-s -w" -o pwa/ygg.wasm ./wasm
```

Android APK（Gradle不使用）: `libyggchat.so`（`GOOS=android GOARCH=arm64` のバイナリ）を `android/` に置いて `android/build.sh`。
`ANDROID_HOME`、`YGG_KEYSTORE`、`YGG_KS_PASS` で SDK と署名鍵を指定できます。GitHub Actions（`.github/workflows/build.yml`）が push ごとにAPKと各バイナリを作り、`v*` タグでReleaseに載せます。署名鍵は `android/yggchat.jks.enc`（AES-256で暗号化）で、復号キーはリポジトリのSecret `KEYSTORE_KEY` にだけあります。Secretがない場合のAPKは使い捨て鍵で署名され、インストール済みのYggChatを上書きできません。PWA（yggchat.surge.sh）の公開はActionsとは別に行っています。

## 検証

`SHA256SUMS` で各ファイルのハッシュを確認できます。バイナリは未署名のため、WindowsではSmartScreenの警告が出ます。
